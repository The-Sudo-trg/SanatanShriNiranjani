# Day 3 — Roles (volunteer pass → account, sadhu approval APIs)

Plan row: Day 3 Roles. Scope per DEVELOPMENT_PLAN.md: sadhu-approval admin
surface, volunteer pass becomes account-based, role guards + wrong-role → 403
e2e.

## Shipped

- **Schema (additive)**: `Volunteer.userId` (optional, `SetNull` on user delete)
  + `User.volunteers[]` back-relation; `scripts/db-sync-schema.mjs` ADD_USERID_COLUMNS
  extended. Old anonymous rows keep `userId = NULL`. Applied locally via
  `prisma db push` and to prod at deploy time by the build's sync script.
- **Volunteer route rewrite** (`app/api/volunteers/route.ts`): `requireRole`
  over every logged-in role (`USER|SADHU|VOLUNTEER|ADMIN`) → 401 guest / 403
  never (all roles allowed) / 400 non-JSON body. `volunteerSchema` is now
  `{ whatsapp }` only — **the pass name comes from the session account
  server-side**; client cannot submit / inject a name (zod strips unknown keys).
- **Sadhu approval APIs** (ADMIN only):
  `GET /api/admin/sadhus` (list, ≤200, public shape) and
  `PATCH /api/admin/sadhus/[id]` `{sadhuVerified}` → `updateMany` filtered
  `where: { id, role: "SADHU" }`, so a USER's own id can never be escalated or
  flagged (404 instead). Console UI deferred to Day 5 per the plan risk note.
- **UI**: guest volunteer modal shows a login-required CTA (strings hardcoded
  Hindi, matching file convention); logged-in users get WhatsApp-only + account
  name note; `DigitalId` renders the real account identity/role (logged-out
  keeps the v1 static card); menu tile shows "सेवा दल पास सक्रिय" chip for
  VOLUNTEERs (new i18n keys hi+en).
- **Tests**: new `tests/unit/roles.test.ts` (real handlers + throwaway DB:
  401/403/404/400/201 contracts, own-id escalation → 404, zod name-strip);
  validators test extends (client name stripped); e2e Day-3 roles test in
  auth.spec (guest 401 → USER 403 list+patch → volunteer 201 with userId) and
  reworked TC-VL-01/02 in flows.spec.
- **TESTING.md**: TC-VL-01/02 re-cut for the account-based pass; TC-AD-01/02
  and TC-RL-01 added.

## Debugging notes (cost us tonight)

1. **TC-VL-02 "no toast"**: dev `prisma/dev.db` lacked `Volunteer.userId` —
   caused by running `prisma db push --schema` with a URL path relative to the
   caller CWD, which prisma resolves relative to *the schema file's directory*:
   it silently synced a nested `prisma/prisma/dev.db` instead. Re-pushed with
   `DATABASE_URL=file:./dev.db`; verified 201 via curl. Verified all admin
   contract codes live: guest admin GET → 401, USER PATCH → 403.
2. Playwright's `request` fixture **persists Set-Cookie like a browser** — the
   "guest 401" assertion must run before the register call that stores the
   session cookie.
3. `DigitalId` now legitimately renders the name twice on /profile and /menu;
   name/role assertions use scoped `.first()`.
